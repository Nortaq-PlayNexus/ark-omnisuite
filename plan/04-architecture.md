# Architecture — implemented prototype

Shared Python standard-library core powers the local HTTP API and optional discord.py bot. This replaces the proposed React/Vite/Tailwind stack to make the small prototype runnable without a package install; the single-page browser UI uses vanilla JS and CSS. Bot uses discord.py v2. Persistent planning data uses browser localStorage; it is not a server database and is not synchronized with Discord. The server provides static assets and narrow JSON calculator endpoints. All values are checked at the core boundary. A validated server-rate INI snippet preview never writes server files. A local experimental RCON CLI exists with a first-packet-only limitation and simulated-server tests; it is not integrated with web or Discord. No scheduler, multi-user security or database are included.

Seed provenance: five explicitly sourced recipe variants (including 2 metal → 1 ingot) are shipped as game data; mutation model cites the assumption in code. User-defined board values are user data. Previously drafted creature, recipe, map and tame data and speculative formulas were removed because they were not reference-verified. Production roadmap requires versioned independently sourced ASE datasets, per-row citations, settings-aware golden comparisons, and robust security before enabling management functionality.

Verification: `python -m unittest discover -s core/tests -v`; `python -m bot.main --dry-run`; start `python -m web.server --host 0.0.0.0 --port 8000`. UI testing and accessibility are not a substitute for a full WCAG audit.
